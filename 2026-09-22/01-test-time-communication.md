## 核心问题

同样启动多个 Agent，允许它们交换发现，能否优于各自探索后取最好结果？重点是探索途中能否累积突破，而非只分配子任务。

## 方法概要

同模型 Agent 使用共享文件系统、追加式通信日志和结果记录，但保留各自上下文。协议要求发布可复现证据、失败信息和方法来源，采纳更优方案时仍保留变体，减少过早趋同。对照为 team@k 与独立 best@k，并分别分析时间和输出 token 成本。[方法与指标](https://arxiv.org/html/2609.21032v1#S2)

## 主要贡献

把“通信有没有帮助”转化为可比较的实验问题；提出可验证进展共享这一机制解释，并用探索游戏与计算优化任务检查其边界。

## 关键实验或结果

| 实验 | 结果与口径 |
| --- | --- |
| ARC-AGI-3，25 个公开游戏 | 完整通关率：team@5 为 8.0%，best@5 为 2.2%；best@33 为 8.1% |
| MNIST 压缩 | 四 Agent、96 小时设置中，最佳产物 1,957 字节，准确率 99.4%；尺寸包含压缩后的推理代码与权重 |
| Terminal-Bench 2.0 | team@2 未超过独立 pass@2，显示收益不普遍 |

ARC 独立基线来自每游戏 64 次试验的组合估计，团队每规模、每游戏 20 次。终点团队实际 token 花费更高，不能把“同每 Agent 资源”说成“同实际总成本”。[正文表 1–2、§3](https://arxiv.org/html/2609.21032v1#S3)

## 适合关注的原因

适合设计自动科研、算法搜索和多 Agent 框架时阅读：是否能快速验证中间结果，可能比角色数量更值得优先设计。

## 局限性或待验证点

作者明确报告低预算协调成本。ARC 绝对通关率仍低、成功集中于少数游戏；64 次独立运行零成功并不证明单 Agent 理论上不可能完成。读者还应检验更大团队、不同模型及噪声验证器下的稳定性。当前空仓库也限制直接复现。

## 对后续研究/应用的启发

我的建议：在自己的任务上固定总预算，对比独立搜索、自由通信、仅共享可验证产物三种模式；同时记录失败传播和重复试验率，检验收益究竟来自信息复用还是额外计算。

## 中文一句速览

有可靠反馈且预算充足时，共享中间证据能让并行搜索形成累积进展。

## 标准化研究框架

**Research question：** 通信能否带来独立并行尝试之外的收益？

**Literature：** 对应 best-of-k、Agent 辩论与自动科研研究；区别在于共享探索产物。

**Theory：** 等价于机制模型：可验证突破被复用，抵消协调成本；并非普适社会理论。

**Hypotheses：** 工程命题而非预注册社会科学假设：充分预算和可靠反馈下通信更有效。

**Method：** 团队与独立搜索对照，结合轨迹案例分析。

**Data and Analysis：** 游戏通关率、优化分数、合格模型字节数及计算成本曲线。

**Findings：** 收益随任务条件变化；具体数值见上表。

**Conclusion：** 应先验证反馈质量与预算条件，再决定是否引入通信。
