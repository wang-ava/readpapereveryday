# SteerBench-Work: A Benchmark for Agent Steering at Action Boundaries

Spotlight：这篇工作切中了 LLM Agent 落地的关键薄弱点——“工具动作前是否应该继续执行”的治理边界，在真实工作场景中以高置信度控制风险，而不是只追求平均能力分。

## 论文内容
- 核心问题：LLM 代理在执行关键工具动作时，如何在“继续执行”与“暂停审核”之间做出可靠决策，是当前可靠性最易失衡的边界。
- 方法概要：构建 incident-anchored 的 `SteerBench-Work`，覆盖开发运维、客服、金融、法律、医疗、HR、安全六大领域，并引入 evidence-reversed mirror（证据反转）样本来模拟误判诱导。
- 主要贡献：
  - 建立单步门控式评测：在一个可复现动作边界上定义“proceed/hold”分类任务。
  - 构建近平衡的两类错误预算（越权放行与过度阻断）以评估风险偏移。
  - 引入真实事件锚点与镜像对照，专门针对模型校准性做验证，而非只做吞吐/正确率评估。
- 关键实验或结果：
  - 抽查 30 个模型条件下，错误主要集中于“过度持有”：授权且证据清晰的场景有 28.1% 被错误 hold；错误放行仅 1.0%。
  - 风险已清除的名人事件镜像样本显著更难，命中率约 63.8%，而原始事件场景 98.5%。
  - 高能力模型并不等于高校准模型，能力增强可能提升或维持放行率，却可能增加“过度保守”问题。
- 适合关注的原因：
  - 这是从“模型能力”走向“治理能力”的关键桥梁，适配企业 Agent、自动化研发助理、财务/客服自动化等场景。
  - 对安全策略团队可直接用于回归测试和阈值标定，减少线上事故。
- 局限性或待验证点：
  - 数据来自公开事件改编，私域高敏场景（如证券交易、临床实际工单）外推仍待验证。
  - 当前评分偏重边界决策正确率，尚未覆盖连续成本与用户体验成本。
- 对后续研究/应用的启发：
  - 代理系统应内置 steering 模块和风险阈值而非只依赖主模型；
  - 可以复用该框架构建行业专属镜像数据集（如法务、SRE、客服）。
- Obsidian 快速浏览一句总结：**最怕“会做”但不敢做，SteerBench 把这一点量化成了可回归的校准指标。**

## 标准化研究框架
**Research question：** 在长期 Agent 工作流中，能否通过标准化边界决策基准，稳定衡量模型在“继续执行”与“持有人类复核”之间的治理能力与校准偏差？

**Literature：** 现有 Agent 评测多数关注成功率/任务完成率，较少显式刻画动作边界风控。该工作在此点上补充了偏差方向与镜像测试的基准设计。

**Theory：** Agent 误行为可分解为两类可量化风险：\*越权放行\*与\*过度阻断\*。若评测仅看总体准确率，容易隐藏方向性偏差而误判部署安全性。

**Hypotheses：**  
- H1：边界分类评测能更好揭示模型校准缺陷。  
- H2：证据反转镜像场景会显著放大越权类风险。  
- H3：更高基准能力并不必然降低越权与阻断的不平衡。

**Method：** 基于 106 个公开事件锚点场景，配对生成可控镜像版本；在每个样本中输入动作描述与证据，模型输出“proceed/hold”；按两种错误方向分别统计命中率与失误率。

**Data and Analysis：** 训练/测试分层采用 incident 与 evidence-reversed 两组；任务标签保持近似平衡；采用按方向的错误率作为主度量，同时比较不同模型能力档位在两方向上的误差结构。

**Findings：** 错误主要偏向“过度保守”，且镜像反转样本显著削弱高风险场景表现，说明模型校准比纯准确率更关键。

**Conclusion：** 在 agent 工作流中，应将 steering 校准纳入上线红线指标；SteerBench-Work 提供了可复用的基准化起点和可解释错误诊断框架。
