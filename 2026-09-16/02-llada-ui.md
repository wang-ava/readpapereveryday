## 核心问题

扩散模型能否从屏幕截图与指令中产生可执行动作，并在连续交互中保持能力及速度优势？例如看到手机文件列表后，输出准确的点击、拖拽或输入操作。

## 方法概要

以 LLaDA2.0-mini-base 为语言骨干，连接原生动态分辨率视觉编码器，形成总参数量 16.7B 的 MoE 模型。先做通用多模态预训练，再用移动端、桌面、网页和定位数据做 GUI 监督微调。通过块内迭代去噪形成动作文本。依据：正文第 2–4 节。

## 主要贡献

把扩散式多模态生成推进到动态 GUI 交互，并提供跨平台评估、解码消融和延迟测量。其研究价值在于检验另一种生成机制是否适合动作输出，而不仅是静态坐标定位。

## 关键实验或结果

- 作者报告在六项 GUI 基准中的四项超过 Qwen3-VL-8B，不能理解为所有平台均领先。见摘要及正文 5.2 节。
- 中间检查点的 AndroidWorld 消融：禁止 EOS 提前结束时成功率为 52.6%，基线为 42.7%；同时增大块长并减少去噪步数时降至 33.0%。这提示速度设置可能破坏动作可靠性，不能把联合改动的效果单独归因于块长。见表 4。
- 表 5 的非缓存 API 均值加速约为网页 3.58 倍、桌面 6.83 倍、移动端 8.95 倍。两模型均使用四张 H100，但每领域只有五次调用，且不含环境重置与动作执行耗时。这是特定输入的单次 API 延迟，非端到端吞吐结论。

## 适合关注的原因

适合关注 GUI Agent、非自回归模型和系统性能的读者。代码与模型入口也使后续验证比仅有摘要的工作更容易启动。

## 局限性或待验证点

延迟样本少且排除缓存命中，不能直接外推到生产负载。模型规模与训练数据并非完全配平，因此基准胜负不能单独证明扩散机制优于自回归。EOS 消融来自中间检查点，仍需在发布模型上验证。

## 对后续研究/应用的启发

**笔记推论：** 复现时应绘制“完整任务成功率—总耗时—调用成本”曲线，并将冷缓存、热缓存、重试和动作解析失败分开统计。可进一步探索按动作难度动态选择去噪步数。

## Obsidian 一句总结

扩散可以生成 GUI 动作，但真正需要优化的是可靠完成任务所需的总时间。

## 标准化研究框架

**Research question：** 块级扩散能否兼顾 GUI 操作能力与交互延迟？

**Literature：** 承接 LLaDA 系列、扩散视觉语言模型及 GUI grounding/navigation 研究；从静态定位延伸到连续执行。

**Theory：** 等价为并行预测、双向上下文和迭代细化的架构动机，并非社会科学解释理论。

**Hypotheses：** 等价工程命题：多模态对齐加 GUI 微调可使扩散骨干胜任交互；解码配置影响可执行性。非预注册社会科学假设检验。

**Method：** 两阶段训练、跨平台基准、解码消融、配对 API 延迟测量。

**Data and Analysis：** 使用移动端、桌面、网页与定位数据，比较基准表现；延迟按领域报告非缓存调用均值、中位数及范围。

**Findings：** 多项基准具有竞争力，部分测量显示较低 API 延迟；激进减少细化步骤会损害成功率。

**Conclusion：** 扩散 GUI Agent 是可行路线，但普遍速度优势与长程可靠性仍需更严格的受控实验。
