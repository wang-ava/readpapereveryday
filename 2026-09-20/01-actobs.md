> **Spotlight：** Agent 训练时，被屏蔽的环境反馈也可能是有价值的监督信号。ActObs 只调整 SFT 的损失掩码，就改变了后续 RL 的探索表现，但多次尝试收益不等于单次成功率全面提升。

# ActObs：让 Agent 学习动作后果

## 核心问题

Agent 常把终端返回内容当上下文，却不学习预测它。仅模仿“该执行什么命令”，是否会损伤理解命令后果的能力，并影响之后的强化学习？例如，模型既要选择命令，也可在训练时预测该命令的输出。

## 方法概要

保留原轨迹，把动作与观察 token 同时纳入 SFT 损失，默认等权；提示词仍屏蔽。随后使用标准 GRPO，部署时仍由真实环境返回观察。主要对照为仅动作监督 ActionSFT，并加入先观察后动作训练等控制。[依据：正文 §2–3](https://arxiv.org/html/2609.20715v1#S2)

## 主要贡献

贡献在于检验一个常被当作默认设置的训练选择：同一批轨迹中的监督位置会影响后续学习。梯度与熵分析进一步把环境预测能力和探索行为联系起来；这些分析支持机制解释，但不能视作普适因果定律。

## 关键实验或结果

两种规模均先用 5 万条终端轨迹训练，再在 2,392 个任务上做 GRPO。表 1 的主要结果如下，数值均为百分比：

| 评估 | ActionSFT→GRPO | ActObs→GRPO |
|---|---:|---:|
| 4B，Terminal-Bench 2.0，pass@1 | 5.6 | 7.2 |
| 8B，同基准，pass@1 | 12.3 | 11.0 |
| 8B，同基准，pass@16 | 23.6 | 27.0 |
| 4B，aider-polyglot，pass@1 | 9.7 | 13.9 |

Terminal-Bench 包含 89 题、每题 16 次尝试；aider-polyglot 包含 225 题。pass@k 表示多次采样中至少成功一次的估计，不能当成单次部署可靠性。[依据：正文表 1、§3，附录 A](https://arxiv.org/html/2609.20715v1#S3)

## 适合关注的原因

对已有 Agent 轨迹库，这是容易设立对照的改动。它也提醒研究者：只按 SFT 后即时得分挑选初始化，可能漏掉更适合继续 RL 的模型。

## 局限性或待验证点

- 证据主要来自终端与代码任务、同一模型家族，不能直接推广到浏览器或具身交互。
- 表中不确定性来自固定题集内重采样，不等于跨任务总体或跨训练种子的稳定性。
- 8B 的单次性能下降是真实取舍；高 pass@k 还需要可靠验收和额外采样预算。
- “预测反馈”是否是主要机制，仍需进一步排除一般多任务正则化等解释。

## 对后续研究 / 应用的启发

建议固定数据和 RL 预算，系统比较观察损失权重，并单独记录单次成功率、总成本及环境预测误差。对噪声日志，可进一步比较全量观察监督和只监督关键状态变化；这是后续研究建议，并非本文已验证结论。

## Obsidian 一句话总结

**学习环境反馈可能改善 Agent 的后续探索，但应同时检查多次采样收益与单次可靠性的取舍。**

## 标准化研究框架

**Research question：** 环境观察监督能否改善 Agent 的 RL 初始化与探索？

**Literature：** 对接动作模仿、语言 Agent 世界建模和可验证奖励 RL；ECHO 是在 RL 阶段加入观察预测的相关比较对象。

**Theory：** 等价于机制解释：联合监督保留动作后果表示，减轻只拟合动作造成的单侧专门化；不是社会科学理论模型。

**Hypotheses：** 等价于工程假设：相同训练条件下，联合监督有利于后续探索与 pass@k；不预设所有规模的 pass@1 都提高。

**Method：** 改变 SFT 损失掩码，固定主实验训练流程，进行方法对照、权重消融与梯度分析。

**Data and Analysis：** 终端轨迹与独立 RL 任务训练，使用终端和代码编辑题集评估；分析成功率、熵及策略位移。

**Findings：** 4B 有单次及跨域收益；8B 更偏向多次采样收益，出现单次性能代价。

**Conclusion：** SFT 应作为后续学习的起点来评估；本文尚不能证明观察监督在所有交互场景均有利。
