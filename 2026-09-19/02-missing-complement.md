# The Missing Complement: State-Conditioned Minimal Sufficient Evidence for Coding Agents

## 核心问题

Agent 已经看到部分证据后，下一步究竟还缺什么？逐段相关性排序可能反复返回同一事实，而遗漏必须同时成立的其他条件。

## 方法概要

SERBench 把轨迹截为明确的决策状态，并用分组证据证书定义充分性：组内来源可以替代，组间要求必须同时满足。MSS-Complement 通过三次语义调用提出组合、寻找缺口、最终选取原始来源片段；输出预算为 4–8 项、最多 6,144 tokens。见正文 §3–5。

## 主要贡献

提出状态条件下的证据补全任务；建立集合完整性评测；用受控比较区分“更强模型带来的收益”和“按集合补缺带来的收益”。这里的最小性约束证书所需条件，不保证返回片段是全局最短组合。

## 关键实验或结果

正文 §6：Test500 来自 45 个与校准集分离的仓库。五项预算下，完整证据集恢复率为 73.0%，Qwen3 embedding 加 reranker 为 61.4%；保留三次调用但按相似性排序的对照为 66.6%。这些是证据完整率，不是 bug 修复成功率。附录另有 Fresh23 端到端修复测试，但只有 23 个任务，不能用其替代大规模真实部署验证。

## 适合关注的原因

适合研究 Agent 记忆、代码 RAG 和多跳检索的人。它将“返回相关片段”变成可检验的决策支持目标，便于发现重复证据占满上下文的失败模式。

## 局限性或待验证点

充分性依赖证书标注及其替代来源覆盖范围。主候选池恢复任务与从整个仓库发现证据是不同难度；论文另设无 gold 派生候选池的检验。输出上下文预算也不等于控制器全部计算开销。组织者保留测试证书，使第三方完整复核依赖评测接口或进一步材料。

## 对后续研究 / 应用的启发

**笔记分析：** 检索日志可显式记录“已知事实”和“未解条件”，先检查覆盖缺口，再决定是否扩展搜索。后续实验应比较证据完整率与实际修复率是否同步提升，并评估错误证书、动态代码和跨语言仓库下的鲁棒性。

## Obsidian 快速浏览总结

**一句话：** 好的 Agent 检索应补齐决策缺口，而不是堆积相似段落。

## 标准化研究框架

**Research question：** 如何在有限上下文内补齐当前代码决策尚缺的证据？

**Literature：** 与 RepoCoder、SWE-agent、代码检索、集合检索和 Agent 记忆研究衔接，具体关系见正文 §2。

**Theory：** 等价于任务形式化：充分性是证据集合属性，单项相关性不保证条件齐全。

**Hypotheses：** 等价于算法假设：状态感知的集合补全优于逐项排序；不是社会科学因果假设。

**Method：** 决策状态捕获、分组证书标注、三阶段补全和匹配计算量对照。

**Data and Analysis：** 以仓库分离测试集评估 Complete-MSS，并辅以发现、定位和小规模修复实验。

**Findings：** 集合目标改善证据完整率，但这与端到端任务成功是不同结果变量。

**Conclusion：** 值得将检索目标改为未满足条件的覆盖，并继续检验真实修复收益。
