## 核心问题

长程 Agent 反复发送工具输出、累积上下文并调用模型，成本可能来自运行流程，而非单次推理。能否自动发现可复用的流程改进，并保留完成任务的能力？

## 方法概要

研究 Agent 从执行轨迹提出候选改动，在开发环境中检查能力和效率，再冻结配置做保留集评估。最终得到四项机制：合并编辑与后续命令；在阶段完成时按成本预测压缩上下文；把重复的大输出替换为可回读句柄；用小模型抽取日志证据并校验，失败则回退原文。细节见正文 §2。

## 主要贡献

将框架优化落实为可执行的搜索与验证流程；展示多个上下文机制组合的收益；提供跨模型后端检验。这里的“递归”不代表已经建立自我改进的普适扩展定律。

## 关键实验或结果

正文表 1–3：在 EdgeBench 上，GPT-5.6 Sol 的完整效率配置相对 Pi 降低 token 流量 49.0%、API 成本 33.2%，但平均得分从 44.833 降至 42.003。Terminal-Bench 4 的 63 个 CPU 任务中，Pi 完成 18 个，SoL-Pi 完成 15 个。不能把降本直接表述为能力完全不变，也不能将 token 流量当作实际运行时间。

## 适合关注的原因

它给长程编码 Agent 提供了具体的工程切入点：记录哪些内容反复进入上下文，以及压缩后能否恢复原始证据。优先阅读机制设计和完整配置的成本—质量权衡。

## 局限性或待验证点

论文的搜索开销与部署节省需要分别核算；性能配置与完整效率配置也需分开比较。上述结果属于有限任务和后端条件，不能保证迁移到私有仓库仍有同等收益。评估的 51 个公开 EdgeBench 任务中，11 个用于冻结候选的单向验收，40 个用于最终泛化评估（§2.5）；不宜统称为完全同质的纯测试集。

## 对后续研究 / 应用的启发

**笔记分析：** 可设计按任务难度分层的质量预算：简单任务积极压缩，证据依赖强的任务保留更多原文。复现实验应同时记录任务完成率、恢复原文次数、缓存费用与总时间，并把搜索研发成本摊销到实际使用量。

## Obsidian 快速浏览总结

**一句话：** SoL-Pi 展示框架级降本空间，但节省多少必须与损失多少任务能力一起看。

## 标准化研究框架

**Research question：** 运行流程能否在限定能力损失下减少 Agent 成本？

**Literature：** 对接自动框架搜索与上下文压缩研究，正文讨论 Meta-Harness、RHI 等路线。

**Theory：** 等价于系统设计依据：减少重复传输和无效交互，保留可恢复证据；不是社会科学理论。

**Hypotheses：** 等价于工程假设：开发环境筛出的机制可在新任务和后端继续获益；不是预注册的社会科学假设检验。

**Method：** 轨迹分析、候选实现、能力与效率筛选、冻结评估。

**Data and Analysis：** 比较任务得分、token 流量和 API 成本，注意配置及测试子集差异。

**Findings：** 成本下降伴随完整配置的部分得分与完成数下降。

**Conclusion：** 支持框架优化的实用价值，尚不能推导无损降本或无限自我改进。
