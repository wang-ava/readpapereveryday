# Necessary or Sufficient? Evaluating LLM Explanations With Behavioural Evidence

## 基本信息

- **作者**：Urja Pawar, Rajitha Ramanayake, Nabeel Kemal, Ashwin Kandath, Owen O'Neill, Guillaume Bourgeon, Houssem Chatbri

- **主题标签**：`LLM` `可解释性` `解释评估` `行为验证` `AI安全`
- **论文链接**：https://arxiv.org/abs/2609.05385
- **PDF 链接**：https://arxiv.org/pdf/2609.05385

## 核心问题
LLM 给出的“依据因素”是否真的驱动了决策？当解释文本很流畅时，是否也说明其可靠性高？本文尝试在可观测决策层验证“必要性”和“充分性”。

## 方法概要
- 在黑盒设定下对模型输出和解释因子做受控干预。
- 定义两类指标：
  - **Necessity（必要性）**：替换某因子后，输出是否改变；
  - **Sufficiency（充分性）**：仅保留该因子时，输出是否保持不变。
- 在两类场景测试：顾问推荐、风险与有害性提示判断。

## 主要贡献
- 给出一套将解释文本映射为行为层因果贡献度的可复现实验框架。
- 直接对比解释排序与必要性/充分性分数，一次性揭示“解释可信度”与“决策驱动”错配。
- 提供跨模型对比（Claude / GPT / Gemini）及跨任务的证据。

## 关键实验或结果
- 在顾问推荐场景，引用排序与必要性/充分性相关系数分别约为 **0.349 / 0.354**。
- 在提示监测场景，相关性分别提升到 **0.431 / 0.580**。
- 超过 **57.6%**（必要性）和 **58.1%**（充分性）的 advisor 场景中，“未被引用的最高分未引用因子”会超越最低引用因子。
- 对提示监测对应比例为 **25.8%**（必要性）和 **8.9%**（充分性）。
- 说明前 3 个解释因子不能稳定代表真实关键因果贡献。

## 适合关注的原因
这类方法把“可解释性指标”从语义说服力拉回决策一致性，对高风险自动化（如风控、审核）中的解释审计尤其关键。

## 局限性或待验证点
- 在实验中基于黑盒干预的解释因子定义较具体，是否适用于代码生成、复杂多步 agent 输出还需验证。
- 结果依赖模型采样策略与温度设置，稳定性边界尚需更系统报告。

## 对后续研究/应用的启发
- 可用于 Agent 监控链路：不仅记录解释文本，还要记录“解释改变时输出是否会变”。
- 在高风险产品上线前，引入必要性-充分性双指标可快速筛出“看似可信但可能不稳”的模型。

## 一句话中文速览总结
论文把解释评估从修辞层降回行为证据，能显著提高对模型决策透明度和可审计性的约束能力。

## 标准化研究框架
- **Research question：** LLM 输出解释中的 top-k 因子是否对应真实的决策驱动力？
- **Literature：** 传统解释评估多依赖一致性问卷、人工标注或注意力映射，缺少对“同一输出在输入干预下的稳定性”做行为约束。
- **Theory：** 若解释可解释因果贡献，则应在干预实验下满足必要性与充分性条件，二者偏离越大，解释可信度越低。
- **Hypotheses：**（1）解释排序与必要性/充分性相关度会显著偏低；（2）不少未被引用的因素仍具高影响力；（3）该偏差在不同模型和任务间普遍存在。
- **Method：** 选择两类任务进行干预实验，比较原始输出、替换因子输出、保留因子输出三类结果；对多个模型做相关统计。
- **Data and Analysis：** 使用 8 个主流模型（Claude/GPT/Gemini 家族成员）在 advisor 与 prompt-monitoring 两套任务上算相关系数与异常率。
- **Findings：** 相关性中等且偏低，且大量未上榜因子仍有显著影响，验证了“解释与真实决策贡献错位”现象。
- **Conclusion：** 对安全与治理场景，解释文本必须配套行为验证，否则会高估模型可审计性。
