# The Menu Is an Execution Prior: State-Path Tool Menus for Online Agents

## 基本信息
- **论文标题**：The Menu Is an Execution Prior: State-Path Tool Menus for Online Agents
- **作者**：Bo Yan, Weikai Lin, Song Wang
- **机构**：arXiv 页面未公开。
- **发布日期 / 版本日期**：2026-09-08（v1）
- **主题标签**：`Agent` `Tool Use` `Online Agents` `LLM` `Execution Planning`
- **论文链接**：https://arxiv.org/abs/2609.09395
- **PDF 链接**：https://arxiv.org/pdf/2609.09395
- **项目/代码/数据链接**：代码：https://github.com/Met2348/State-Path；数据/基准：ToolBench（论文评测来源）。

## 核心问题
在线 agent 往往面对上千工具，直接让模型自己选择可能错过关键前置工具。论文探讨：能否通过“状态路径”学习工具执行序列先验，从而显著提高多步任务成功率。

## 方法概要
作者将可选工具集合改为“短菜单（tool menu）”的执行优先级问题：
- 用状态表示当前可执行性；
- 检索执行链中的缺失输入提供者与最终执行者；
- 按工具间顺序重排，优先把前置 producer 放在前面；
- 在同一条请求下只暴露一组有序候选菜单，减少无关调用。

## 主要贡献
- 给出 State-Path 工具菜单的新建模框架，不再把调用排序完全交给 LLM 端临场生成。
- 同时兼顾检索、路由和重排三类传统基线。
- 保持执行器不变，仅替换工具输入接口逻辑，便于工程接入。

## 关键实验或结果
- 在 ToolBench 上，在线成功率从 `0.737` 提升到 `0.898`。
- 在“覆盖更多完整工具链路”评价上，官方完整列表 128 个工具的覆盖不及该方法的 `32` 工具链路覆盖（作者报告）。
- 成功率提升在不同执行器（模型能力）上保持。

## 适合关注的原因
论文把“工具链可行性”显式建模为先验，避免单点召回偏差，适合企业级工作流（工具数量大、流程固定、错误成本高）的在线 agent 系统；尤其对长链路任务的鲁棒性有直接意义。

## 局限性或待验证点
- 论文强调 ToolBench 评测，真实企业工具生态可能有更复杂权限与副作用。
- 额外依赖状态路径标注质量；当执行历史稀疏时效果边界未充分披露。
- 公开结果未展开对显著不相关工具极端情况下的退化曲线。

## 对后续研究/应用的启发
- 在流程自动化平台可直接作为工具层策略替代：先筛“路径可行”再交给 planner。
- 可与反思/验证模块联动，将执行失败反向更新工具菜单。
- 对多 agent 协同可做子任务级菜单共享与迁移。

## 一句话中文速览总结
把“下一步能做什么”改为“先把状态路径中的关键工具找齐”，显著降低在线 agent 的工具遗忘与链路断裂。

## 标准化研究框架
- **Research question：** 工具菜单中的执行先验能否显著提高在线 Agent 的多步任务成功率？
- **Literature：** 传统方法更偏向相关性检索和 rerank，常忽略工具间输入输出依赖。
- **Theory：** 若显式建模状态到目标动作的可执行路径，agent 的动作空间可被结构化约束，降低错误组合搜索。
- **Hypotheses：**（1）菜单化工具约束提高关键 producer-consumer 的召回；（2）在线成功率显著提升；（3）不同 executor 下提升具有稳定性。
- **Method：** 将状态-动作链映射为 state-path，训练检索器与重排器并与基线进行 ToolBench 对比。
- **Data and Analysis：** 以 ToolBench 多步任务、官方工具集合与模型不同能力族为主测项，分析成功率和链覆盖指标。
- **Findings：** 该方法在公开评测中取得从 0.737 到 0.898 的成功率提升，体现路径优先约束优势。
- **Conclusion：** 对强工程化 Agent 系统，状态路径菜单是提升可靠性的实用替代方案，但仍需与真实安全治理联动。
